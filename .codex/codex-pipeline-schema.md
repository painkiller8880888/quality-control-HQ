# schema.md — テンプレート定義集

> `codex-pipeline-personal.md`（本体）の3章フローで使う各テンプレートの最小定義。フロー・役割分担など運用の考え方は本体を参照。

---

## 要求最小テンプレート

```markdown
## 目的
このタスクで達成したいことを書く。

## 現在の挙動 / 期待する挙動
今何が起きていて、変更後どうなってほしいか。

## 受入条件
- AC-1:
- AC-2:

## 制約・非対象
守るべき制約と、今回は変更しない範囲。
```

大きめのタスクなら「関連ファイル」「再現手順」を足す程度でよい。

---

## 調査結果（Scout）の最小テンプレート

読み取り専用調査でLuna（Terra）がSol Chatへ返す内容。「確認できなかった点」は空欄にせず、無ければ「なし」と書かせて省略と未確認を区別する。

```markdown
## 関連ファイル
## 現状の実装（該当箇所の要約）
## 依存関係・既存テストの状態
## 確認できなかった点
```

## Plan最小テンプレート（Sol Chatが作成）

```markdown
## 要求の要約
## 不確実性（あれば調査タスクにする）
## 変更候補（ファイル・領域と理由）
## 実装手順
## 検証コマンド
## 初期モデルと理由（原則Luna）
## 昇格条件（本体4章の基準を当てはめる）
## Codexへの実行指示
```

## PR本文の最小テンプレート

```markdown
## 変更目的 / 変更内容

## 受入条件との対応
| AC | 状態 | 根拠 |
|---|---|---|
| AC-1 | PASS/FAIL/未確認 |  |

## 実行した検証コマンドと結果

## 未確認事項

## 既知のリスク
```

DB状態やスクリーンショットなど、実際に必要な証跡だけを足せばよい。個人開発では最初からすべての項目を用意する必要はない。

## AGENTS.md 最小テンプレート

```markdown

## 完了の基準
コードを書いただけでは完了ではない。受入条件との対応、検証結果、未確認事項がPRに書かれていて初めて完了とする。
```
