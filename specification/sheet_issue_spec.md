# 検査書発行機能仕様書

## 0. 現行実装同期（2026-07-15）

- 通常の発行対象はクラス1/6/7、明示クラス9は常に対象。対象ごとの `issue_status` と History の `is_sheet_issued` を更新する。
- 対象ID指定印刷、コード指定のopen/pdf/print、日別一括発行を提供する。
- 発行APIは Job を作成し 202 を返すが、現状はレスポンス前にExcel/印刷処理を同期実行する。真のバックグラウンド処理ではない。
- `pending / issued / missing_file / skipped / not_required` を保持するが、プリンタが受理したことと紙の出力完了を同一視できるかは未決である。

### 正式リリース向け優先事項

| priority | 要件 | 受入基準 |
|---|---|---|
| Critical | Excel/プリンタの実行環境固定 | サービスアカウント、Excel版、マクロ署名、既定プリンタ、共有権限を手順化し実機で再現できる |
| Critical | 非同期化と排他 | APIを短時間で受付終了し、同一ファイル/プリンタの競合を防ぎ、ジョブ再起動後も状態が追跡できる |
| Critical | 発行結果の定義 | issued に遷移する時点、部分成功、再印刷、重複防止を業務承認し試験する |
| High | 障害復旧 | COM失敗、ファイルロック、紙切れ、共有断、プロセス残留から安全に再実行できる |
| High | 監査 | 実行者、対象、時刻、結果、再実行を機密情報なしで追跡できる |

## 1. 目的
- 検査に必要な検査書（Excelファイル）の印刷処理をバックエンドから自動実行し、ペーパーレスまたは自動印刷によって現場の準備工数を削減する。
- 検査実績（履歴）と連動し、時間帯ごとの印刷ステータスを追跡できるようにする。

## 2. 処理フロー

```mermaid
sequenceDiagram
    autonumber
    actor User as 検査員 (フロントエンド)
    participant BE as バックエンド (Django)
    participant Excel as Excelマクロ (Windows)
    participant DB as データベース

    User->>BE: 印刷指示 (対象コード、時間帯、ファイルパス、現在時刻)
    Note over BE: Job登録後、現状はHTTP内で同期実行
    BE->>Excel: Excel起動 & 引数 (ファイルパス、現在時刻) を渡してマクロ実行
    Active Excel
    Note over Excel: 1. 指定ファイルを開く<br/>2. 日付・時刻を転記<br/>3. 押印枠の設定<br/>4. 計測以外のチェック自動入力<br/>5. プリンタへ印刷出力<br/>6. 保存せずにファイルを閉じる
    Excel-->>BE: 実行完了シグナル
    Deactive Excel
    BE->>DB: historyテーブルの該当レコードの is_sheet_issued を True に更新
    BE-->>User: 印刷完了通知 (次のバッチ処理へ)
```

### 2.1 印刷指示の受信 (フロントエンド → バックエンド)
- ユーザーはフロントエンドUIから、特定の品目および時間帯を指定して印刷処理を指示する。
- 一括印刷（バッチ処理）の指示も可能とする。

### 2.2 バックエンドによるExcelマクロの制御
- バックエンドはWindows環境下で動作するDjangoサーバーとして、COMコンポーネント（`pywin32` / `win32com` など）を介してExcelを操作する。
- Excelマクロに対して以下のパラメータを引数として渡す。
  - 制御対象の検査書ファイルの絶対パス
  - 印刷指示された日付・時刻

### 2.3 Excelマクロ内の自動処理
- **ファイルオープン**: 指定された検査書ファイルを開く。
- **日付・時刻の転記**: 検査書内の所定セルに日付・時刻を書き込む。
- **押印枠の処理**: 押印枠へのデータ入力（または画像配置など）。
- **チェック処理**: 計測項目以外の点検項目に対し、自動的にチェック（レ点など）を記入する。
- **印刷**: 指定された物理プリンタ、またはPDF等へ出力する。
- **ファイルクローズ**: 変更内容を保存せず（または別名保存し）、ファイルを閉じる。

### 2.4 実績・履歴への反映
- マクロ実行の完了を検知したバックエンドは、該当する日付・品目・時間帯に対応する `history` レコードを取得（または作成）し、`is_sheet_issued` フラグを `True` に更新する。
- 複数件のバッチ処理の場合は、1件の処理が完了するごとに履歴を更新し、次のファイルの処理へ進む。
