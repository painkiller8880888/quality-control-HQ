# EXCELテンプレートファイルの仕様について

 - テスト環境ではプロジェクト外のexcelファイルは全て/tempにて同名ファイルを参照する。

## 0. 現行連携と正式リリース前の確認（2026-07-15）

- 日報生成/印刷、検査書印刷は Windows 上の Excel COM/マクロとローカルまたは共有ファイルに依存する。
- API は Job レコードを作るが、現状はHTTP処理内で同期実行する。同一ブックへの並行操作を直列化する共通ロックは保証されていない。
- `daily.xlsm` の配布版、マクロ署名、Trust Center 設定、プリンタ名、サービス実行アカウント、共有フォルダ権限、Excelダイアログ抑止は環境ごとの未決事項である。

Critical受入基準: 専用サービスアカウントで無人実行し、同時要求が直列化され、Excelプロセスが残留せず、ファイル使用中・プリンタ停止・マクロ無効・共有切断から安全に復旧できること。テンプレートの版とハッシュを配布手順で固定し、バックアップから復元試験を行うこと。

## 1. 日報テンプレート /excel/daily.xlsm　`daily`シート

 - 「日報」シートへ品名を貼り付けて使用する。
 - A～Dの時間帯別に、C列、F列、I列、L列にそれぞれの時間帯の品名を貼り付ける。
 - `class_no`別に、18行目からは`6`、22行目からは`7`、26行目から`1`、35行目から`9`、4行目からは`2`、`3`、`8`を貼り付ける。
 - `4`、`5`は品名を貼り付けず、時間帯別の総数をカウントして38行目に貼り付ける。
 - 日報シートのみ/reportsにyyyymmdd.xlsxの形式で保存する。

## 1.1 検査書印刷マクロ /excel/daily.xlsm 内の RunBatch()マクロ

 - `data` シートの内容を引数として任意の検査書ブックを起動、内容を記入して印刷する。この処理はバッチ化されており、pythonからリストを1回だけ流すことで一括で処理を行える。
 - `data` シートへの入力規則は以下の通り。2行目以降にリストを入力する。
 -- A列: 検査書ブックのファイルパス。
 -- B列: A～Dの時間帯。
 -- C列: 検査対象品目の`class_no`
 -- D列: 検査日付のシリアル値。
 -- E列: 検査者ID。(MVPでは`1-6`)
 -- F列: 検査者氏名。 (MVPでは`前田 賢一`)

 ## 2 工程内検査履歴.xlsx パスは設定UIから指定

 - 期ごとにシート分けされた履歴の保管ファイル。期は10月始まりで、10月時点の(y - 1956)で求められる。
 - このファイルに保存されるのは`class_no`が`1`の検査結果のみ。
 - シートの内容は以下の通り。
 -- B列: 日付。
 -- C列: 検査時間。時間帯がAとBなら`AM`、CとDなら`PM`を記入。
 -- D列: 品目コード。
 -- E列: 品名。
 -- F列: 合否判定。常に`合格`で入力。
