## 4.ERPとSQLのテーブル構造
- 製品はERPにおいて複数のノードを内包するコンテナとして表現される。それぞれのノードは生産工程を表現するため階層化している。(以降この構造のことを「構成」と呼ぶ)各ノードは固有のIDであるコード(アルファベット3ケタ+数字4ケタ)と名称、階層レベル、担当部署、仕様数量などのフィールドを持つ。各ノードはコードの頭文字を取って略称される。
 - A/Bコード: 組み立てが終わり、商品・製品の状態として出荷できる状態のノード。
 - Cコード: 中途段階の梱包、組立、切削、塗装、メッキ、プレスなどの加工状態のノード。
 - Dコード: ネジ、バネ、磁石、樹脂部品、キャスト部品などの単体部品のノード。
 - Eコード: 鉄材のコイルなど原料のノード。
- ERPから出力される構成データは上から順に処理する。階層レベルnのノードは、その行より上方にある最も近い階層レベルn-1のノードの子ノードとして扱う。
- ERPから抽出した構成データはノード自体のマスタテーブルとノードの親子関係のテーブルに分割され、SQLに登録される。その際ノードの循環参照をチェックする。
- 検査対象には作業の種類による6つのカテゴリがあり、コードによって判別可能。検査書の発行が必要となるのは1と6のみ。発行に使うexcelのマクロはコードのみ必要となる。
 - 1: 自動機。完全に自立して動く自動機械による組立。
 - 2: 半自動機。人間が部品のフィードを担当する自動機械による組立。
 - 3: 手動。全て人間の手による組立。
 - 4: プレス。社内プレス機による成形。
 - 5: 二次加工。社内加工器械による加工。
 - 6: 製品検査。社外委託した組立工程の検査。

master
-----------
master_id	(主キー)
code		(コード)
name		(名称)
node_type	(作業種類)
department	(担当部署)
category	(カテゴリ) 

structure (parent_codeとchild_codeをインデックスする)
-----------------
structure_id	(主キー)
root_code		(構成内のルートノード)
parent_code		(親ノード)
child_code		(子ノード)
level			(親ノードの階層レベル)
quantity		(使用数量)

UNIQUE(parent_code, child_code)
- 検査書のファイル名は必ずコードを含む。ファイル名をコード名で検索し、合致したコードを検査コードとしてSQLに登録する。

inspection
--------------
inspection_id	(主キー)
master_id		(FK → master.master_id)
file			(ファイル名)
path			(ファイルの場所)

- 作業計画のOCRデータ、作業計画ファイルからはユニークなコードのみを抽出し、検査対象コードを取り込む。ユーザーはUI上でこれらのコードに割り振られたA～Dの4つのチェックボックスに対し、検査を行った時間帯と合致した箇所をチェックする。作業日報が発行されると同時にこれらのデータを検査履歴デートしてSQLに保管する。

history
------------
history_id	(主キー)
date		(日付)
master_id	(FK → master.master_id)
time		(時間帯A～D)

UNIQUE(date, master_id, time)
- 自動機械にはそれぞれ担当する部品コードがあり、すべてがユニークな番号を割り振られている。1つの機械が複数のコードを担当する、あるいは複数の機械が同一のコードを担当する場合がある。

machines
----------------------
machine_id		(主キー)
machine_no		(機械No.)
machine_name	(機械名称)
map_x			(見取り図中心X座標)
map_y			(見取り図中心Y座標)
shape_type      (circle / ellipse / polygon)
width           (図形幅)
height          (図形高さ)

machine_assignments
----------------------
machine_assignments_id	(主キー)
machine_id				(FK → machines.machine_id)
code					(FK → master.code)

UNIQUE(machine_id, code)
