# 日報アプリ仕様書

## 1. アプリの目的・機能
- 工場内巡回検査履歴の作成を補助し、日報を発行する。
- 作業計画のスキャンPDFデータをOCRし、また社内サーバーのexcel計画表データを取り込み、包括的な検査対象リストをデジタルな形で作成する。これは手動入力にも対応する。
- 検査履歴は検査対象リストと検査済みチェックによって構成される。検査チェックは営業時間を4分割したセクションに対し、検査を行った時間に該当する箇所にチェックすることで行われる。
- 自動加工機械と検査対象リストを紐づけ、巡回すべき機械を工場見取り図上でマークする。見取り図はマウスオーバーで表示されるツールチップを備え、機械の名前と担当品目を表示する。
- 検査書の発行が必要な品目に対し、必要情報を入力した状態で印刷を行う。(excelマクロとして実装済み)
- 必要なデータをexcelファイルに入力し、検査日報を発行する。
- 検査履歴をデータベースに保管し、所定の形式でexcelに入力する。
- ERPの自動操作、社内サーバーの横断検索によって品目データを更新する。
- (将来実装)社内サーバーでのオンプレミス化の際に問題が起きないように調整する。

## 3. パイプライン
0. データベースの更新 (フロント→バックエンド→windows→データベース)
UIから情報更新が指示された時、pythonの自動化でERPパッケージを操作してcsvファイルを出力し、データベースに取り込む。また、検査書フォルダを走査してパスとファイル名を取得し、データベースに取り込む。

1. 作業計画の取り込み (フロント→バックエンド→データベース)
スキャンデータのOCRと指定されたexcelファイルの計画データを抽出してデータベースと照合し、検査対象品目のリストを生成する。スキャンデータはD&Dによる自動処理に対応。
 
2. 検査計画表の作成 (バックエンド→フロント)
検査対象品目ごとに、4つのチェックボックスのUIを設ける。これは営業時間を4分割したセクションに対応し、UI上でチェックすることで検査済を意味する。

3. 検査ガイドの表示 (データベース→バックエンド→フロント)
加工機械と加工品目を紐づけたデータベースと検査対象品目のリストに基づき、巡回すべき機械をUIの見取り図上でマークする。見取り図はすべての機械についてマウスオーバーで表示するツールチップを設け、機械の名前と担当品目を表示する。

4. 検査書の発行 (フロント→バックエンド→excel)
データベース上で検査書発行必須のマークが付いた検査対象品目について、検査書を発行する。excelマクロとして実装済の検査書発行プロトコルを実行する。一括発行と個別発行が選択可能で、一括発行を行うと発行済の品目はマークされ、次回の一括発行の対象とならない。

5. 作業日報・履歴の作成 (フロント→バックエンド→データベース→excel)
作業内容をデータベースに保管し、内容を所定のフォーマットでexcelにコピーして作業日報を発行する。このバックアップ作業は実行されるたびに常にその日の最新の状態に上書きで更新される。

REST API形式を利用。
GET    : データ取得
POST   : 新規作成・実行
PUT    : 全更新
PATCH  : 部分更新
DELETE : 削除
